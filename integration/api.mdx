`https://api.basestonk.io` - what BaseStonk's own interface reads. No key
for reads. The v4 accounting is already done; raw-chain integrations that
assume v2/v3 pairs read \$0 liquidity.

Machine client? The same surface under `/api/v1` adds coded errors, one
envelope, an OpenAPI document and the `/prepare` endpoints -
[AI agents](/integration/agents).

## The chain

| `{chain}` | Id | Explorer |
|---|---|---|
| `base` | 8453 | Basescan |
| `robinhood` | 4663 | Blockscout |

`?chain=` on token and wallet routes; a path segment on venue routes.
Wrong chain for a token is `404`, never the other index. Endpoints that
exist on one chain only are marked.

## Rate limits

Per client IP, per minute, cost-weighted:

| Lane | Budget | Covers |
|---|---|---|
| `api` | **120 units** | every `/api/*` read |
| `paircheck` | 30 | pair-check lookups |
| `uploads` | 6 | image and metadata uploads |
| `ingest` | 20 | error and CSP reports |

| Operation | Units |
|---|---:|
| any read | 1 |
| per 100 rows in `limit` | +1 |
| catalogue search (`q=`) | +5 |
| a `/prepare` call | +10 |

Responses carry `x-ratelimit-limit` and `x-ratelimit-remaining`. Exhausted:

```json
HTTP 429   retry-after: 21
{ "error": "rate limited", "retryAfter": 21 }
```

<Warning>
**A 429 is "refused", never "empty".** Honour `retry-after`. Prefer one batched call over per-item loops.
</Warning>

## Errors

| Status | Body | Do |
|---|---|---|
| `400` | `{"error":"unknown chain"}` | use `base` or `robinhood` |
| `400` | `{"error":"invalid address"}` | fix it; do not retry unchanged |
| `400` | `{"error":"bad interval"}` | pick from the candles list |
| `400` | `{"error":{...}}` | fix the named fields |
| `404` | `{"error":"token not found"}` | verify; do not loop |
| `429` | `{"error":"rate limited","retryAfter":n}` | wait, then resume |
| `503` | `{"error":"..."}` | capped exponential backoff |

## Pagination

`limit` and `offset`. One envelope: `{ "sort", "total", "hasNext", "tokens": [...] }`.

| Endpoint | Default | Max |
|---|---|---|
| `/tokens` | 24 | 200 |
| `/tokens/{address}/candles` | 300 | 1000 |
| `/tokens/{address}/trades`, `/holders` | 25 | 200 |
| `/ecosystem` | 50 | 1000 |
| `/basket-assets` | 200 | 1000 |

Responses evolve **additively**. Ignore unknown fields. `taxBps` is
backfilled for pre-V6 launches whose `buyTaxBps`/`sellTaxBps` are null;
treat it as both directions.

## Endpoints

### Tokens

| | |
|---|---|
| `GET /api/launchpad/tokens?chain={chain}` | every launch: pair, hook, price, cap, volume, holders, tax |
| `GET /api/launchpad/tokens/{address}?chain={chain}` | one token |
| `GET /api/launchpad/tokens/{address}/candles?interval=1m&chain={chain}` | `1s` `5s` `15s` `1m` `5m` `15m` `1h`; default `5m` |
| `GET /api/launchpad/tokens/{address}/trades?chain={chain}` | |
| `GET /api/launchpad/tokens/{address}/holders?chain={chain}` | |
| `GET /api/launchpad/tokens/{address}/rewards/{wallet}?chain={chain}` | received so far plus live pending |

`/tokens` filters: `sort` (`trending` `age` `marketcap` `volume` `holders`), `dir`, `q`, `pair`, `generation` (`v1`..`v6` `simple` `b20`), `features`.

### Wallets

| | |
|---|---|
| `GET /api/launchpad/holders/{address}/tokens?chain={chain}` | every BaseStonk token the wallet holds |
| `GET /api/launchpad/creators/{address}/tokens?chain={chain}` | every token it launched |

### Pairs and pricing

| | Chains | |
|---|---|---|
| `GET /api/launchpad/pairusd/{chain}?pair=0x…` | both | USD per pair token, from the registry the launcher prices with |
| `GET /api/launchpad/paircheck/{chain}?pair=0x…` | both | can this address be launched against right now - `hasMarket` needs \$2,500 of depth on Base - and why not |
| `GET /api/launchpad/ecosystem/{chain}` | both | the chain's pair catalogue - see below |
| `GET /api/launchpad/basket-assets/base` | Base | the basket-eligible menu: `registered` (curated set, with `category`, `launchable`, `needsIssuance`) plus `ecosystem` (ranked, priced rows; paged) |
| `GET /api/launchpad/gatedroute/base?pair=0x…` | Base | gate-verified route, `issuerFactory` (zero for a creator-chosen pair), `usdPerPair` - for **any** token address, not only catalogued ones |

**`/ecosystem`**: on Base, `eco` (`clanker` `virtuals` `bankr`) browses one catalogue, absent browses all three; on Robinhood Chain, the 194 stocks, `eco` not applicable. `q` searches name, symbol or address on either.

### Venue

| | Chains | |
|---|---|---|
| `GET /api/launchpad/stats/{chain}` | both | that chain's tokens, trades, volume, holders - plus a `venue` block summed across both chains. `venue.aggregated` names the summed fields; \$BSTONK's burn is deliberately not one. |
| `GET /api/launchpad/burn/base` | Base | \$BSTONK burn totals |

<Note>
Eligibility is the chain's word, not this cache's. On-chain vetting and rebuild rules: [on-chain page](/integration/onchain#launching-programmatically).
</Note>
