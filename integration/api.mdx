`https://api.basestonk.io` - what BaseStonk's own interface reads. No key
for reads. The v4 accounting is already done; raw-chain integrations that
assume v2/v3 pairs read \$0 liquidity.

Machine client? The same surface under `/api/v1` adds coded errors, one
envelope, an OpenAPI document and the `/prepare` endpoints -
[AI agents](/integration/agents).

## The chain

| `{chain}` | Id | Explorer |
|---|---|---|
| `base` | 8453 | Basescan |
| `robinhood` | 4663 | Blockscout |

`?chain=` on token and wallet routes; a path segment on venue routes.
Wrong chain for a token is `404`, never the other index. Endpoints that
exist on one chain only are marked.

## Rate limits

Per client IP, per minute, cost-weighted:

| Lane | Budget | Covers |
|---|---|---|
| `api` | **120 units** | every `/api/*` read |
| `paircheck` | 30 | pair-check lookups |
| `uploads` | 6 | image and metadata uploads |
| `ingest` | 20 | error and CSP reports |

| Operation | Units |
|---|---:|
| any read | 1 |
| per 100 rows in `limit` | +1 |
| catalogue search (`q=`) | +5 |
| a `/prepare` call | +10 |

Responses carry `x-ratelimit-limit` and `x-ratelimit-remaining`. Exhausted:

```json
HTTP 429   retry-after: 21
{ "error": "rate limited", "retryAfter": 21 }
```

<Warning>
**A 429 is "refused", never "empty".** Honour `retry-after`. Prefer one batched call over per-item loops.
</Warning>

## Errors

| Status | Body | Do |
|---|---|---|
| `400` | `{"error":"unknown chain"}` | use `base` or `robinhood` |
| `400` | `{"error":"invalid address"}` | fix it; do not retry unchanged |
| `400` | `{"error":"bad interval"}` | pick from the candles list |
| `400` | `{"error":{...}}` | fix the named fields |
| `404` | `{"error":"token not found"}` | verify; do not loop |
| `429` | `{"error":"rate limited","retryAfter":n}` | wait, then resume |
| `503` | `{"error":"..."}` | capped exponential backoff |

## Pagination

`limit` and `offset`. One envelope: `{ "sort", "total", "hasNext", "tokens": [...] }`.

| Endpoint | Default | Max |
|---|---|---|
| `/tokens` | 24 | 200 |
| `/tokens/{address}/candles` | 300 | 1000 |
| `/tokens/{address}/trades`, `/holders` | 25 | 200 |
| `/ecosystem` | 50 | 1000 |
| `/basket-assets` | 200 | 1000 |

Responses evolve **additively**. Ignore unknown fields. `taxBps` is
backfilled for pre-V6 launches whose `buyTaxBps`/`sellTaxBps` are null;
treat it as both directions.

## Endpoints

### Tokens

```bash
GET /api/launchpad/tokens?chain={chain}
```

Every launch with pair, hook, price, market cap, volume, holders and tax.
Filters: `sort` (`trending` `age` `marketcap` `volume` `holders`), `dir`,
`q`, `pair` (an address, or `crypto` / `memes` / `stocks`), `generation`
(`v1`..`v6` `simple` `b20`), `features` (comma-separated AND of
`platform` `og` `rewards` `buyback` `auto-liquidity` `simple` `advanced`),
`addresses` (up to 50 - a watchlist in one call).

```bash
GET /api/launchpad/tokens/{address}?chain={chain}
```

One token. Add `tx=<launch hash>` and a token not yet indexed is indexed
from that receipt on the spot.

```bash
GET /api/launchpad/tokens/{address}/candles?chain={chain}&interval=1m
```

`interval`: `1s` `5s` `15s` `1m` `5m` `15m` `1h` (default `5m`).
`before=<unix seconds>` pages backwards through history.

```bash
GET /api/launchpad/tokens/{address}/trades?chain={chain}
GET /api/launchpad/tokens/{address}/holders?chain={chain}
GET /api/launchpad/tokens/{address}/pressure?chain={chain}
```

Trades take `trader=` and `side=`. Holders take `q=` (an address prefix,
four or more hex characters). Pressure is the momentum panel: buys, sells,
volume and distinct wallets over 5m / 1h / 4h / 24h.

### Wallets

```bash
GET /api/launchpad/holders/{address}/tokens
GET /api/launchpad/creators/{address}/tokens?chain={chain}
GET /api/launchpad/wallets/{address}/positions?chain={chain}
GET /api/launchpad/rewards/{address}?chain={chain}
GET /api/launchpad/tokens/{token}/rewards/{address}?chain={chain}
```

Holdings are cross-chain and take no `chain`. Positions are the
portfolio's PnL rows - entry, holding, realised, unrealised - and take
`token=` to narrow. Rewards are dividends received across every token, or
on one token with the live pending amount.

### Pairs and pricing

```bash
GET /api/launchpad/pairusd/{chain}?pair=0x…
GET /api/launchpad/pairusd-batch/{chain}?pairs=0x…,0x…
GET /api/launchpad/paircheck/{chain}?pair=0x…
GET /api/launchpad/pair-identity/{chain}/{address}
GET /api/launchpad/ecosystem/{chain}
```

`pairusd` is USD per pair token from the registry the launcher prices
with; the batch form takes up to 120. `paircheck` answers whether an
address can be launched against right now - `hasMarket` needs \$2,500 of
depth on Base - and names any namesake risk. `pair-identity` resolves
symbol, name and artwork for any address, curated or not.

`ecosystem` is the chain's pair catalogue. On Base, `eco` (`clanker`
`virtuals` `bankr`) browses one catalogue and absent browses all three;
on Robinhood Chain it is the 194 stocks. `q` searches name, symbol or
address.

```bash
GET /api/launchpad/basket-assets/base
GET /api/launchpad/gatedroute/base?pair=0x…
```

Base only. `basket-assets` is the dividend-basket menu - `registered`
(the curated set, with `category`, `launchable`, `needsIssuance`) plus
`ecosystem` (ranked, paged). `gatedroute` returns the gate-verified route,
`issuerFactory` (zero for a creator-chosen pair) and `usdPerPair` for
**any** address with a market - what `launchGated` takes.

### Venue

```bash
GET /api/launchpad/stats/{chain}
GET /api/launchpad/burn/base
GET /api/launchpad/burn/base/history
```

`stats` is that chain's tokens, trades, volume and holders, plus a
`venue` block summed across both chains (`venue.aggregated` names the
summed fields; \$BSTONK's burn is deliberately not one). `burn` is the
\$BSTONK burn total; `history` is the daily series.

### Live updates

```
wss://api.basestonk.io/ws
```

Send `{ "subscribe": ["tokens:new", "token:0x…", "candles:0x…:1m"] }`.
Events: `token.new`, `token.trade`, `token.touched`, `token.state`. The
site's list and charts run on this; polling is the fallback.

### Images

```bash
GET /api/img/{address}?chain={chain}&w=64
GET /api/card/token/{chain}/{address}.png
```

Resized token artwork, and the 1200x630 share card the site unfurls.
